# 던만추 인생 시뮬레이터 v1.7.5 — 설계 정리 + 2a (주 개발자 제출)

대상: QA_AUDIT_v1.7.4의 설계 오류 5건, 그리고 QA가 권고한 "2a만 진행".

## 1. 설계 오류 5건 정리 (`DESIGN_PROPOSAL_status_separation.md` §7 정정, §8 신설)

| # | 지적 | 정리 |
|---|---|---|
| 1 | 명성 단계 불일치(`city`/`orario`) | `unknown → local → orario → major`(무명/지역 명성/오라리오 명성/유력 파밀리아)로 통일. 코드 `GameCore.Recruit.FAME_STAGES`, 테스트가 enum과 표시명 일치를 강제. 문서에 `city` 잔존 0 |
| 2 | 입단-팔나 시점 충돌 | §8.1 표로 분리: **목표 규칙**(입단 확정 순간 팔나, 지연은 사유 이벤트만; 3단계·승인 후) / **임시 규칙**(현행 `falnaAt` 유지; ~2c). 2a~2c는 임시 규칙만 구현 |
| 3 | 파밀리아 명성 보존 | `familiaFame`을 `membershipId`별 맵으로 변경. 소속 이력에 순차 `id` 추가(구현됨). 이적해도 기록 보존, 재가입은 새 id, `familiaId` 합산은 표시용 |
| 4 | scout/god_whim 경로 | `admitDirect(S, familiaId, route, reason)` 정의(§8.3): `current` 미경유, `initiator:'god'`, 같은 파밀리아 신청이 있으면 그 신청을 닫음, 새 membershipId 생성, 이적 제한은 원작 근거 전까지 미구현 |
| 5 | 업적 귀속 | §8.4 credit 스키마: 공개 여부, 당시 membershipId, 공개된 소속, 귀속 대상, `retroactive:false`. 입단 전·소속 비공개 업적은 개인에게만, 기록은 수정·재귀속 금지 |

QA §6 권고 4건도 §8.5에 반영했습니다(minor 예약어·비공식 표시·파생 RNG, 명성 효과는 모집 경로 개방 우선, canon 임의 자격 금지, 범위 2a). 총괄 최종 승인은 별도입니다.

## 2. 2a 구현 — 동작 연결 없음

- `core/recruit.js`: 명성 단계·경로 7종·결과 5종·`INITIATORS`, **비어 있는 동결 `RECRUIT_TUNING`**, 파생 RNG(`createDerivedRng`), 비공식 minor 파밀리아 생성기(`createMinorFamilias`; 예약어/게임 데이터 라벨과 겹치면 제외, `official:false`, 비공식 표시). **게임 코드는 생성기를 호출하지 않습니다.** 이 모듈은 `Math.random`을 사용하지 않습니다(테스트가 소스 문자열로 확인).
- `data.js`: 파밀리아 14개에 `kind:'canon'`, `official:true`. `S.application`({current:null, history:[]}), `S.minorFamilias:[]`, `S.nextMembershipId`, 소속 이력 `id` 추가. 이들은 난수를 소비하지 않습니다.
- 유의: minor 이름 음절·성향·목적 목록은 **임시 중립 단어**이며 원작 조사 후 확정해야 합니다. 예약어 목록도 제가 아는 이름만 담은 불완전한 목록입니다(원작 고유명 확장 필요).

## 3. 동작 불변 증명 (같은 시드 회귀 비교)

러너에 생애 요약 해시 `lifeDigest`(나이·레벨·직업·소속·HP·재화·사망 원인·이벤트 순서열)를 추가하고, v1.7.4에 같은 패치를 적용한 기준과 비교했습니다. 기준값은 `logs/baseline_lifeDigest_v174.json`, 비교 도구는 `tests/regression_digest.js`입니다.

```
SAME physical/20261104, physical/777, physical/314159, physical/8675309,
     calendar/20261104, newborn_parent_familia/20261104   → PASS: 6개 구성 모두 기준과 동일 (각 3,000생애)
```
- 처음 구현했을 때 새 단위 테스트가 본 시뮬레이션의 난수열을 소비해 해시가 달라졌습니다(게임 변경이 아니라 테스트 부작용). 난수 상태를 저장·복원하도록 고쳐 해결했고, 이 사실은 증명이 단순한 "숫자 우연 일치"가 아님을 보여 줍니다.
- 4시드 × 4모드 × 3,000판 다중 시드 통계(`logs/multi_seed_stats.log`)를 재실행했을 때 `통합`·`시드별`·`소속 이력` 모든 수치가 v1.7.4 로그와 동일했습니다(diff 0). `off` 모드 등 해시 기준에 없는 구성도 통계가 같습니다.
- `lifeDigest`는 요약 해시이므로 상세 상태 전부의 동일성이 아니라 위 필드의 동일성 증명입니다.
