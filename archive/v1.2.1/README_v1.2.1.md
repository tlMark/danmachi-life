# 던만추 인생 시뮬레이터 - v1.7 통합본 (기준: v1.2.1 chatgpt_reviewed)

## v1.7 변경 요약 (자세한 내용은 `DEV_REPORT_v1.7.md`)

- 가족 NPC(부모·손위 형제·동생·자녀)를 `S.relations`에 실제 생성하고, 연애 후보에서 영구 제외합니다. 종족 규칙: 제노스는 가족 없음, 아마조네스는 어머니만, 하프엘프는 엘프·휴먼 부모.
- 가족·파트너 NPC도 종족·팔나·레벨에 따른 육체 나이로 늙고, 자연사/사고사합니다. 파트너 사별·이별을 구분해 기록하며 종료된 관계는 덮어쓰지 않습니다.
- 이벤트 조건 `cond.age`는 육체 나이(`S.phase`), 신규 `cond.cage`는 달력 나이(`S.age`)입니다. 입단·징집·진로·의식 이벤트는 달력 나이를 씁니다.
- 연간 직업 활동 엑세리아(`ANNUAL_ACTIVITY`), 팔나 수령 시 잠재력 이월, 레벨 단계별 위업 이벤트를 추가해 Lv6 이상과 `hero_sacrifice`가 실제로 도달 가능합니다. 수치는 모두 임의 밸런스 값입니다.
- 아이템: 무기·방어구는 장착(슬롯당 최고 1개), 소모품은 사용 횟수(`maxUses`)가 있고 전투력 판정·체력 위기에서 자동 사용됩니다(`core/items.js`).
- Ares·Kali는 기존 정책(둘 다 `soldier`)을 유지합니다. 파밀리아와 직업은 독립이며 가입은 기존 직업을 덮어쓰지 않습니다.
- 테스트: `node test_runner.js`(실제 소스 3,000판 + 단위 테스트), `node tests/browser_test.js`(실제 Chromium). 로그는 `logs/`에 있습니다.


## 실행

`index.html`을 브라우저에서 열면 됩니다. 외부 npm 패키지는 사용하지 않습니다.

`index.html`은 다음 순서로 브라우저 모듈을 불러옵니다.

1. `data.js`
2. `events.js`
3. `core/aging.js`
4. `core/growth.js`
5. `core/relations.js`
6. `core/items.js`
7. `script.js`

`core/*.js`는 브라우저 전역 `GameCore`에 등록되는 모듈이며 CommonJS `require`나 `module.exports`, `uuid`에 의존하지 않습니다.

## 이번 검토 반영

- 결과 화면 문자열을 `\n`이 포함된 유효한 JS와 `join('\n')` 방식으로 재작성했습니다. 기존 `script.js`의 따옴표 문자열 줄바꿈 문법 오류를 제거했습니다.
- 노화 처리를 `GameCore.Aging`으로 분리했습니다. 실제 상태 구조인 `S.race.id` 및 `MODS.races`를 사용하고, 종족·팔나 레벨 보정을 모두 적용한 최종 노화율의 하한을 0.1로 보장합니다. 실제 나이(`S.age`/`S.chronologicalAge`)와 육체 나이(`S.physicalAge`/`S.phase`)를 별도 관리합니다.
- 성장 처리를 `GameCore.Growth`로 분리했습니다. 팔나 전 경험은 `S.potential`, 팔나 후 경험은 `S.excelia`에 분리 기록합니다. 실제 게임 능력치 구조 `S.abil`의 `str/vit/dex/agi/mag`를 사용하고, 비유한 값·음수·상한 초과를 방어합니다. 일반 능력치 상한은 999, 리아리스 보유 시 1499입니다.
- 연애 관계 처리를 `GameCore.Relations`로 분리했습니다. 양쪽 모두 만 18세 이상, 나이 차이 10년 이하, 가족/친족이 아닐 것, 생존 상태일 것을 검사합니다. 한 번에 활성 연인은 한 명만 허용하며 기존 연인이 사망하면 연결을 해제합니다.
- 기존 `partner` 플래그 의존 이벤트 3개(`love`, `amazon_duel`, `have_child`)를 `hasPartner` 조건과 실제 관계 객체로 전환했습니다.
- 존재하지 않는 `core/simulator.js`를 호출하던 이전 테스트러너를 교체했습니다. 실제 브라우저 게임 흐름을 모의 DOM에서 실행하고, 첫 예외에서 fail-fast 합니다. 은퇴 여부가 아니라 사망/종료 상태를 기준으로 각 생애를 진행합니다.
- `blacksmith_forge` 이벤트는 현재 직업 경로상 팔나와 동시에 성립하지 않아 발생하지 않는 조건이었습니다. 대장장이 직업 이벤트이므로 팔나 요구 조건을 제거했습니다.

## ChatGPT 최종 통합 검토 반영 — 2026-11-04

- 관계 ID 생성 시 저장 데이터의 카운터가 오래되었거나 충돌해도 기존 관계 객체를 삭제하지 않고 고유 ID를 다시 할당합니다.
- 기존 지인 관계의 `type`/`subType`을 보존하면서 연애 상태를 별도 필드(`isPartner`, `relationshipStatus`)로 관리합니다.
- 명시적 이별 처리(`endRelationship`)와 사망 처리 훅(`partnerDeath`)을 추가했습니다. `relationship_crisis` 이벤트에서 이별 선택과 실패 분기가 실제 `ended` 상태를 설정합니다. 단, NPC의 종족·수명·팔나 레벨 데이터가 없으므로 자연 사망 판정은 아직 구현하지 않았습니다.
- 팔나 후 새 엑세리아가 없더라도 위업(feat)만으로 레벨업 조건이 충족되는 경우 레벨업 검사를 다시 수행합니다.
- 파밀리아 기본 직업은 명시적 직업 매핑(예: 헤파이스토스→대장장이)을 우선하고, 이미 선택한 직업(예: 서포터)은 파밀리아 가입으로 덮어쓰지 않습니다. 팔나 취득만으로 모험자 직업 플래그를 부여하지 않습니다.
- 모의 DOM 통합 테스트에 화면 전환, 자동 진행, 파밀리아 직업 매핑, 관계 종료 및 레벨업 회귀 테스트를 추가했습니다.

### 확인했으나 미해결인 항목

- 파트너 자연 사망: 3,000판에서 0회. 명시적 사망 처리 훅은 있으나 이를 발생시키는 수명/사망 시스템 또는 이벤트가 없습니다. 100세 파트너가 활성 상태로 남는 동작을 별도 단위 테스트로 재현했습니다.
- 가족 관계 생성: 자연 플레이 3,000판에서 부모·형제자매 등 가족 관계 레코드가 0건 생성됐습니다. 가족을 연애 대상에서 제외하는 판정은 통과하지만 실제 가족 NPC 생성 시스템은 아직 없습니다.
- 레벨업 밸런스: 능력치 하나가 500(D랭크) 이상이어야 하는 조건이 병목입니다. 3,000판 중 최종 레벨 분포는 Lv0 1,337 / Lv1 1,568 / Lv2 82 / Lv3 11 / Lv4 2, 최고 Lv4입니다. Lv2 이상은 95/3,000(3.17%)입니다. 팔나 보유자 중 능력치 500 이상은 `r3_balance.js` 기준 약 0.1%이며, 레벨업 가능성 차단의 대부분이 능력치 부족에서 발생했습니다.
- `hero_sacrifice`는 Lv6 조건으로 3,000판에서 미발생했습니다. 현행 성장 규칙을 유지한다면 엑세리아 배분과 위업 공급 이벤트를 먼저 조정해야 합니다.
- 팔나 취득 직후 전투력 계산은 `potential` 기반에서 능력치/hidden/레벨 기반으로 전환되지만, 기존 `potential`을 엑세리아 등으로 변환하지 않습니다. 초기 능력치가 낮으면 취득 시 전투력이 급락할 수 있어 의도 확인이 필요합니다.
- 이벤트의 `cond.age`는 여전히 육체 나이(`S.phase`)를 사용합니다. 사회적·직업적·법적 나이 조건까지 노화 억제를 따라 늦어질 수 있으므로, 연대기 나이 조건과 육체 나이 조건을 분리할 필요가 있습니다.
- 아이템 데이터의 `type`/`maxUses`와 실제 인벤토리/장착/사용 흐름은 아직 완전히 연결되지 않았습니다.
- 실제 Chromium UI 검증은 수행하지 못했습니다. 제공된 `r3_browser.js`/`r3_auto.js`는 Playwright를 요구하지만 현재 테스트 환경에 Playwright가 없습니다. 아래 화면/자동 진행 결과는 확장한 Mock DOM 테스트입니다.

### 원작 설정 참고의 적용 범위
