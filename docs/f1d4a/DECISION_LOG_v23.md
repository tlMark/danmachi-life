## 기입 규칙

1. 이 표에는 **사용자가 실제로 결정·승인한 내용만** 적는다. Claude의 제안이나 권장은 적지 않는다.
2. 단계는 서로 다른 열로 기록하고, 한 단계의 기록을 다른 단계로 옮겨 적지 않는다.
   - 설계 결정
   - 구현 착수 승인
   - 기능 활성화 승인
   - 실제 시험 결과
3. **하위 결정은 각각 독립 행이다.**
   - 예: A1 수치와 A1-연령, D1 자격·가중치와 D1-확률, C1 조건과 C1-직업
   - 한 행을 결정해도 다른 행은 결정된 것이 아니다.
4. **구현 착수 승인 열에는 묶음 단위 승인만 적는다.**
   - 예: "A 묶음 착수 승인 2026-xx-xx"
   - 상위 A~G 진행 승인(2026-11-21)은 아래 '상위 승인' 표에만 적는다. 각 묶음의 착수 승인으로 중복 기록하지 않는다.
   - 같은 묶음에 속한 행에는 같은 승인 기록을 참조 표시(→ 묶음 승인 행)로만 적는다.
5. 실제 시험 결과 열에는 실행한 결과만 적는다. 실행 전에는 BLOCKED 또는 미실행으로 둔다.
6. 빈칸은 "아직 없음"이다. 빈칸을 승인이나 통과로 읽지 않는다.
7. **변경 이력 원칙 (R10).** 이미 기록한 사용자 결정·승인을 수정하거나 철회할 때 기존 기록을 **덮어쓰거나 지우지 않는다.**
   - 아래 '변경 이력' 표에 새 행을 추가한다: 날짜, 대상 항목, 이전 기록(원문 그대로), 변경 사유, 새 결정 내용(또는 "철회"), 출처.
   - 항목별 표의 원래 칸에는 이전 기록을 그대로 두고, 그 뒤에 `→ 변경 이력 #n 참조`만 덧붙인다.
   - 철회된 결정에 근거한 구현 착수 승인·활성화 승인·시험 결과는 자동으로 유지되지 않는다. 그 영향은 변경 이력 행의 사유 칸에 적고, 다시 승인받는다.
   - 결정 기록 문서의 판(v1, v2, v3 …)도 덮어쓰지 않고 보존한다.
