# p1_verify 기준선 비교 항목의 의미 (2026-11-28 기준, 문서 전용)

- 근거
  - ChatGPT 1차 QA "main 병합 및 G1 기준선 검수 결과" §4·§5 참고 사항("역사적 비교와 필수 비교의 의미를 문서화")
  - DECISION_LOG v23(새 기준선 인정 2026-11-28)
- 이 문서는 **현재 규칙을 설명할 뿐 바꾸지 않는다.** 판정 상태와 종료 코드 계약을 바꾸는 일은 검증 정책 변경이며, 별도 사용자 승인이 필요하다.

## 1. 비교 항목

| 항목 | 기준(폴더) | 현재 기대 결과 | 의미 |
|---|---|---|---|
| 05g · 06g | G1 기준선 `logs/baseline_main_605fdf4`(P4 + G1-가) | **동일**(필수) | 현재 승인된 게임 결과와의 대조다. "다름"이면 의도하지 않은 결과 변경이거나, 아직 승인되지 않은 의도적 변경이다 |
| 05p · 06p | P5 기준선 `logs/baseline_main_3859123` | 다름(실패 기록) | 역사적 비교: P4·G1-가 이전 결과와 비교한다 |
| 05m · 06m | main f63c851 기준선 `logs/baseline_main_f63c851` | 다름(실패 기록) | 역사적 비교 |
| 05 · 06 | F1 기록 `logs/v178_f1` | 다름(실패 기록) | 역사적 비교 |

## 2. 결과 읽는 법(현재 계약 그대로)

- p1_verify 의 종료 코드는 위 역사적 비교 6항목 때문에 **1(실패)** 이다. 이 종료 코드를 성공으로 해석하지 않는다.
- 변경 하나를 판정할 때는 세 가지를 함께 본다.
  - 05g·06g 가 동일인가
  - 그 밖의 항목(문법·시험·Chromium·RNG 대조 등)이 모두 exit 0 인가
  - 실패 목록이 정확히 역사적 6항목(05·05m·05p·06·06m·06p)뿐인가
- 결과를 바꾸는 의도적 변경이 승인되면 새 기준선 폴더를 만들고 비교 항목을 하나 더 둔다. 기존 폴더는 덮어쓰지 않는다.

## 3. 향후 정책 변경 시 지켜야 할 것(제안, 미승인)

- 역사적 비교 기록은 삭제하지 않는다.
- 필수 실패(판정에 쓰는 항목)와 참고 비교(기록만 남기는 항목)를 상태 기록에서 구분한다.
- 종료 코드 계약을 함께 바꾸고, 그 계약을 검사하는 시험(`tests/verify_run_selftest.sh` 등)을 추가한다.
