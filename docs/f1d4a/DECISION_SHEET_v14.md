- **Proxy (R17)**
  - Proxy를 일반 객체와 완벽하게 구별할 수 있다고 주장하지 않는다. 표준 JavaScript에는 그런 수단이 없다.

  - 트랩이 단계마다 다른 값을 돌려주더라도, 순서 3 이후에는 확보한 지역 사본만 쓰므로 집계가 검증된 값과 어긋나지 않는다.
  - 정상 코드에서 `S.eventCounts`·`S.flags`에 Proxy를 대입하는 경로는 없다(생애 초기화, script.js:1032-1035).

**정상 배열 판별 절차 (R21, v5 기준을 대체)**

v5 기준은 `Array.isArray(p) && Object.getPrototypeOf(Object.getPrototypeOf(p)) === null`이었다. 이 기준은 **반례가 있어 폐기한다.**
- 반례: 배열 `y`의 프로토타입을 `Object.prototype`으로 바꾸고, 그 `y`를 다른 배열의 프로토타입으로 쓴다.
- 이때 `Array.isArray(y)`가 참이고 `y`의 프로토타입의 프로토타입이 `null`이므로 v5 기준을 통과한다. 그런데 `y`는 기본 `Array.prototype`이 아니다.
- Node v22에서 실행해 v5 기준이 이 반례를 통과시키는 것을 확인했다.

v6 기준은 다음 6단계다. 모두 순서 0의 예외 차단 구역 안에서 실행하고, 앞 단계에서 실패하면 멈춘다.

| 단계 | 검사 | 목적 |
|---|---|---|
| F1 | `Array.isArray(a)`가 참 | 배열이 아닌 값 거부 |
| F2 | `p = Object.getPrototypeOf(a)`가 `null`이 아님 | 프로토타입 null 배열 거부 |
| F3 | `Array.isArray(p)`가 참이고, `p`의 프로토타입 `pp`가 `null`이 아니며 `pp`의 프로토타입이 `null` | 하위 클래스(`Sub.prototype`은 배열이 아님) 거부, 2단 이상 체인 거부 |
| F4 | `p`의 own `constructor`가 **데이터 descriptor**이고 그 값 `C`가 함수 | 생성자 정보가 없는 사용자 정의 배열 프로토타입 거부 |
| F5 | `C`의 own `prototype`이 데이터 descriptor이고 그 값이 정확히 `p` | 다른 realm의 `Array`를 빌려 붙인 가짜 거부(`Array.prototype !== p`) |
| F6 | `Function.prototype.toString.call(C)`(검사하는 쪽 realm의 원본 함수)가 `/^function Array\(\) \{\s*\[native code\]\s*\}$/`와 일치 | 이름이 `Array`인 사용자 함수, 바인드 함수, 함수 Proxy 거부. 이 셋은 각각 소스 문자열이 나오거나 이름이 비어 있다. 기존 `CHOICE_NATIVE_OBJECT_SRC`(script.js:222)와 같은 방식이다. **F6은 진위의 완전한 증명이 아니라 fail-closed 방어다.** 원생 함수처럼 보이는 문자열을 돌려주는 다른 경로가 있을 수 있으므로, 통과를 "원생 Array 확정"으로 해석하지 않는다. F4·F5와 함께 써서 알려진 반례를 거부하는 용도다 |
| F4·F5 공통 (R21 보완) | `constructor`·`prototype` 모두 `Object.getOwnPropertyDescriptor`로 own descriptor를 얻는다. **own 속성이 없거나**(상속만 있음) 접근자 descriptor이면 실패다. 이후에는 descriptor의 `value`만 쓰고, `p.constructor`·`C.prototype` 같은 **일반 속성 접근은 다시 하지 않는다**(getter 실행, 트랩 재호출, 값 변경 사이의 불일치 방지) | 확보한 값만 사용 |

이어서 own 키 검사를 한다(v5와 같다). `"0"`…`"length-1"`과 `"length"` 밖의 키(추가 own 속성, 심볼 키)가 있으면 `flags_shape`다.

**반례 검토 (Node v22에서 판별 절차를 일회성으로 실행한 결과, 저장소 시험 아님)**

| 사례 | v5 기준 | v6 결과 | 실패 단계 |
|---|---|---|---|
| 일반 배열 `[]` | 정상 | **정상** | — |
| 다른 realm(`vm.runInNewContext("[]")`)의 기본 배열 | 정상 | **정상** | — |
| 하위 클래스 `class Sub extends Array` 인스턴스 | 거부 | 거부 | F3 |
| 사용자 정의 배열 프로토타입(위 반례) | **통과(결함)** | 거부 | F4 |
| 위 반례 + `y.constructor = Array` | — | 거부 | F5 |
| 위 반례 + 바인드 함수에 `prototype = y`를 붙인 생성자 | — | 거부 | F6 |
| 위 반례 + `function Array(){}`(사용자 함수) 생성자 | — | 거부 | F6 |
| 위 반례 + `new Proxy(Array, {})` 생성자 | — | 거부 | F5 |
| 프로토타입 null 배열 | 거부 | 거부 | F2 |

- **허용 범위:** 어느 realm이든 그 realm의 **기본 `Array.prototype`을 직접 프로토타입으로 가진 배열**만 정상이다.
  - 다른 realm의 `Array.prototype.constructor`가 바뀌어 있으면 그 realm의 배열도 거부된다(fail-closed). 정상 게임 코드는 이 속성을 바꾸지 않는다.
- **남는 한계:**
  - Proxy는 트랩이 기본 배열과 같은 응답을 일관되게 돌려주면 정상으로 판정된다. 이는 R17의 "보고하는 대로 판정" 원칙과 같다. 구별할 수 있다고 주장하지 않는다.
  - Proxy 불변식 때문에, 대상의 설정 불가 속성(예: `Array.prototype`)을 다르게 보고하는 트랩은 엔진이 TypeError를 던진다. 이 경우는 `flags_access_error`가 된다.

- **flags 진단 구분 (R20):** 배열 형태 오류(`flags_shape`)와 항목 오류(`flags_item`)를 **구분한다**. 형태 검사가 먼저이고, 형태가 비정상이면 항목 검사는 하지 않는다. 예외는 단계와 관계없이 `flags_access_error`다.
- **적용 범위:** 거짓이 되는 것은 **그 입력을 읽는 조건**뿐이다.
  - 그 조건을 가진 후보는 빠진다.
  - 그 입력을 읽지 않는 후보는 영향을 받지 않는다. 예: `minLevel`만 있는 luck은 `eventCounts`가 망가지거나 검증 중 예외가 나도 후보로 남는다.
- **후보 생성은 중단되지 않는다 (R17):**
  - 세 입력(eventCounts·job·flags)을 후보 평가 **전에** 각각 독립된 예외 차단 구역에서 한 번씩 검증하고, 결과(정상 사본 또는 무효 표시)를 지역 변수에 둔다. 구역은 `S.eventCounts`·`S.job`·`S.flags` **속성 읽기부터** 시작한다(R22).
  - 한 입력의 예외가 다른 입력의 검증이나 후보 평가를 막지 않는다.
  - 후보 평가는 이 지역 결과만 읽는다.
- **진단:** S 밖의 기존 `devAbilityDiagLog`에 `devability_eligibility_invalid`를 남긴다. 내용은 `{ input, reason }`이다.
  - 후보 생성 1회 호출에서 **입력별 최대 1건**이다. 처음 실패한 reason 하나를 남긴다.
  - 같은 입력을 읽는 후보가 여럿이어도 1건이다.
  - **진단 기록 실패 계약 (R22):** 진단 기록(`devAbilityDiagLog`에 추가)은 따로 예외 차단 구역에서 한다.
    - 실패해도 판정 결과는 바뀌지 않는다. 예외는 바깥으로 던지지 않는다.
    - 다시 시도하지 않는다. 대체 기록도 S에 남기지 않는다.
    - 다른 입력의 진단 기록 시도와 후보 평가는 계속된다.
- **불변:** 예외를 던지지 않는다. `S`를 읽기만 한다(쓰기 0). `Math.random` 호출 0. 진단 기록은 lifeDigest·RNG에 관여하지 않는다.
- **정의 데이터 쪽:** `eligibility.job` 항목이 허용 직업 id가 아니거나 `eligibility.flags` 항목이 빈 문자열·비문자열이면 정의 오류다. `definition_invalid`로 처리한다(D1-S 스키마 검증, 상태 입력 오류와 별개 경로).

**데이터 스키마 (D1-S1~S4 권장안 기준의 제안)**

```
  flags?: [<flag 문자열>, …]                   // 선택. 현재 S.flags 가 모두 포함해야 함
```

- 정의 검증(`validateDevAbilityDefs`) 확장
  - 허용 키는 위 4개뿐이다. 그 밖의 키, 빈 배열, 문자열이 아닌 항목, 정수가 아니거나 범위를 벗어난 값이 있으면 `definition_invalid`로 처리한다(기존 DEV-12 경로).
  - `areaEventCountMin.area`는 `EVENT_AREA`에 실제로 쓰이는 분류 이름이어야 한다.
- 후보 생성(`devAbilityCandidates`) 확장

  - 모든 조건은 AND로 묶는다.
  - D1-S5의 fail-closed 규칙을 적용한다.

**후보 평가 호출 기록의 정의 (R22, v9 신설)**

P11a·P12a~c의 "호출 기록이 같다"는 아래 정의로 비교한다.

| 항목 | 규칙 |
|---|---|
| 기록 단위 | 후보 하나의 자격 평가 1회 = 기록 1건: `{ seq, candidateId, inputs }`. `seq`는 0부터 시작하는 평가 순서다. 기록 배열의 순서는 실제 평가 순서다 |
| `inputs` = 정규화된 검증 스냅숏 | 원래 S 값이 아니라 **검증 단계의 결과**를 기록한다. `inputs`는 정확히 세 키 `eventCounts`, `flags`, `job`을 가진다. 모든 기록에 **세 입력 객체가 항상 존재한다.** 해당 후보가 쓰지 않는 입력이어도, 상태가 어떻든 마찬가지다. 각 입력 객체의 고정 스키마는 아래 **입력별 고정 직렬화 스키마**에 있다 |
| 키 순서 | 객체 키는 UTF-16 코드 단위 기준 사전순으로 정렬해 직렬화한다(`JSON.stringify`의 삽입 순서에 의존하지 않음) |
| 배열 순서 | 기록 배열은 `seq` 순서. `flags.values`는 위 규칙대로 정렬된 순서. 그 밖의 배열은 쓰지 않는다 |
| 누락 필드 | 정의된 필드는 빠뜨리지 않는다. 값이 없음을 나타내야 할 때는 `null`을 명시한다. `undefined`는 쓰지 않는다(직렬화에서 사라지므로) |
| 특수값 | 스냅숏에는 NaN·±Infinity·-0·함수·심볼·BigInt가 **들어가지 않는다.** 검증을 통과하지 못한 값은 `status: "invalid"`와 reason 문자열로만 나타난다. 그래도 계측기가 이런 값을 만나면 그 시험은 **오류(통과 아님)**로 처리한다 |
| 직렬화 결과 | 위 규칙의 정규 JSON 문자열. 실행 (i)·(ii)의 기록 문자열이 바이트 단위로 같아야 "같다"로 판정한다 |
| 계측 비간섭 | 계측기는 다음을 지킨다.<br>① 평가 함수에 넘기는 인자를 바꾸거나 감싸지 않는다(같은 참조를 그대로 전달)<br>② 평가의 반환값을 바꾸지 않는다<br>③ 기록은 평가 **직후** 직렬화한 **문자열**로만 남기고, 인자 객체의 참조를 보관하지 않는다<br>④ 난수·S·진단 배열에 접근하지 않는다<br>⑤ 계측을 켠 실행과 끈 실행의 후보 결과(id 목록)와 S 직렬화가 같음을 대조 시험(DA-S4m)으로 확인한다 |
| 측정 분리 | 진단 배열 측정(P11b)과 후보 평가 기록은 **따로 보고**한다. 한쪽 결과로 다른 쪽의 합격을 대신하지 않는다 |

**입력별 고정 직렬화 스키마 (R5, v10 신설)**

모든 입력 객체는 **정확히 세 키** `status`, `value`, `reason`을 가진다. 키 집합은 상태와 관계없이 바뀌지 않는다.

| 입력 | `status` | `value` | `reason` |
|---|---|---|---|
| `eventCounts` | `"ok"` | 0 이상의 안전한 정수(`dungeonCount`, 집계 결과) | `null` |
| `eventCounts` | `"invalid"` | `null` | `"eventCounts_shape"`·`"eventCounts_key"`·`"eventCounts_value"`·`"eventCounts_overflow"`·`"eventCounts_access_error"` 중 하나 |
| `job` | `"ok"` | 허용 직업 id 문자열 | `null` |
| `job` | `"invalid"` | `null` | `"job_value"`·`"job_access_error"` 중 하나 |
| `flags` | `"ok"` | 문자열 배열(중복 제거, UTF-16 사전순). 빈 배열 `[]` 허용 | `null` |
| `flags` | `"invalid"` | `null` | `"flags_shape"`·`"flags_item"`·`"flags_access_error"` 중 하나 |

- **배타 규칙:** `status`가 `"ok"`면 `value`는 `null`이 아니고 `reason`은 `null`이다. `status`가 `"invalid"`면 `value`는 `null`이고 `reason`은 위 목록의 문자열이다. **`value`와 `reason`이 둘 다 값을 갖거나 둘 다 `null`인 경우는 허용하지 않는다.**
- **사용하지 않는 필드:** 위 표에서 `null`인 필드는 생략하지 않고 `null`로 적는다.
- **위반 처리:** 계측기가 이 스키마를 만족하지 않는 객체를 만들면(키 누락·추가, 배타 위반, 목록 밖 reason, 형식 위반) 그 시험 실행은 **계측 오류**다. 통과로 세지 않는다.
- **직렬화:** 위 객체를 앞 표의 키 순서·배열 순서·특수값 규칙으로 직렬화한다. 예:

